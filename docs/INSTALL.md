# Neurover MCP — установка и аккаунты

Локальный MCP для Neurover. Работает с медиатекой, галереей очистки, полотнами и генерациями через neurover.io. Сервер автора для работы не нужен.

## Установка

Нужен Node.js **22.16 или новее** с npm: https://nodejs.org/. Поддерживаются современные macOS, Windows и Linux на архитектурах, для которых поставляется нативная библиотека @napi-rs/keyring.

1. Распакуйте чистый архив в постоянную личную папку. Не запускайте программу от администратора/root.
2. macOS: откройте `install.command`. Windows: `install.cmd`. Linux: `sh install.sh`. Если macOS ограничивает запуск скачанного скрипта, прочитайте его и выполните `sh install.sh` в терминале.
3. Установщик загрузит зависимости из npm и Chromium средствами Playwright, затем откроет локальную настройку. Настройки MCP-клиентов он автоматически не изменяет и платных генераций не запускает.
4. Введите имя аккаунта, email и выберите, кто будет входить заново, когда Neurover завершит сессию: вы вручную или MCP сам (пароль в хранилище ОС). Разница объяснена ниже в «Как устроен вход». Пароль вводится только в вашем терминале без отображения либо на neurover.io в отдельном окне. Не отправляйте его в чат.
5. Скопируйте показанные `command`, `args`, `env` в настройки локального stdio MCP. JSON целиком подходит клиентам с полем `mcpServers`; в остальных внесите те же поля в их формат.

При переносе программы или Node.js заново выполните `node bin/neurover.mjs config` и обновите путь подключения. Обновление программы должно сохранять папку данных.

Если Chromium не запускается на Linux из-за библиотек, изучите требования `npx playwright install-deps chromium`. Можно выбрать однократный вход в терминале без браузера; графическая сессия для него не требуется.

## Как устроен вход

MCP ходит в Neurover по **сессии сайта** (cookies). Сессия появляется после входа и сохраняется на этом компьютере; пока она действует, пароль не нужен. Neurover время от времени завершает сессию, например после бездействия. Тогда нужен новый вход, и при установке вы выбираете, **кто его будет делать**.

Важно различать две вещи:

- **Войти** (через окно браузера или вводом пароля в терминале) — получить новую сессию. Это разовое действие, пароль при этом не сохраняется.
- **Сохранить пароль** — разрешить MCP самому входить заново, когда сессия закончится.

| | 1. Ручной вход (по умолчанию) | 2. Системное хранилище |
|---|---|---|
| Что хранится | только сессия | сессия и пароль в хранилище ОС |
| Сессия закончилась | MCP отвечает `login_required`; вы выполняете `node bin/neurover.mjs login ACCOUNT` и входите снова | MCP сам входит заново и повторяет запрос |
| Подходит | редкое использование, не хотите хранить пароль | регулярная работа, долгие фоновые задания (очистка, генерации) |

Если сайт часто выбрасывает из-за бездействия, а вы пользуетесь MCP постоянно, выбирайте **2**: иначе входить вручную придётся после каждого перерыва.

**Системное хранилище** — это macOS Keychain, Windows Credential Manager или Linux Secret Service. В конфигурации MCP и локальных файлах пароля нет. ОС может запросить разрешение или разблокировку; приложение не обходит её защиту. Отдельного мастер-пароля MCP нет. Режим можно поменять в любой момент: `node bin/neurover.mjs settings ACCOUNT`.

На Linux необходимы пользовательский D-Bus и доступная служба `org.freedesktop.secrets`: например GNOME Keyring либо совместимая реализация KWallet с включённым Secret Service. На сервере без такой службы доступен ручной режим. Библиотека принудительно использует Secret Service: скрытого перехода к временному kernel keyring или открытому файлу нет. Список совместимых реализаций: https://github.com/Brooooooklyn/keyring-node#linux-backend-selection.

Если хранилище отсутствует, заблокировано или доступ отклонён, операция сообщит об ошибке. Это не повод сохранять пароль в файл. Возможность автовхода зависит от состояния хранилища и сессии ОС; отсутствие запросов разрешения не гарантируется.

В **обоих режимах** cookies сайта сохраняются локально для фоновых заданий. Они также дают доступ к аккаунту. Без сохранения пароля не означает без сохранения сессии. Папка данных должна быть личной. Для браузерного входа используется временный контекст Chromium.

## Изменение настроек

```sh
node bin/neurover.mjs setup
node bin/neurover.mjs accounts
node bin/neurover.mjs settings ACCOUNT
node bin/neurover.mjs login ACCOUNT
node bin/neurover.mjs config
node bin/neurover.mjs doctor
```

`ACCOUNT` — ваше имя аккаунта. `settings` переключает режим и позволяет обновить сохранённый пароль. Переход в ручной режим сначала отключает автовход, затем удаляет запись этой реализации из системного хранилища и старый локальный файл пароля. При ошибке остаётся ручной режим с `password removal pending`; разблокируйте хранилище/исправьте доступ и повторите настройки. Программа не утверждает, что удаление удалось, если оно завершилось ошибкой. Email существующего имени не меняется: для другого email добавьте новое имя.

Старый режим plain больше не используется для автовхода: `settings` переводит его в системное хранение или ручной вход и удаляет прежний файл. Ранее настроенные encrypted-аккаунты продолжают работать до переключения; `unlock`/`lock` оставлены только для совместимости. Новые такие аккаунты не создаются. Старые аккаунты другой macOS-реализации продолжают читать прежнюю запись Keychain до выбора нового режима; чужая запись не удаляется.

Инструмент `neurover_account_setup` возвращает безопасную команду для вашего терминала; `neurover_account_settings` — режим без секретов. Пароли не принимаются через аргументы CLI, MCP или env.

## Данные и распространение

- macOS: `~/Library/Application Support/NeuroverMCP`.
- Windows: `%LOCALAPPDATA%\NeuroverMCP`.
- Linux: `$XDG_DATA_HOME/neurover-mcp`, обычно `~/.local/share/neurover-mcp`.
- `NEUROVER_DATA_DIR`: необязательный абсолютный путь, одинаковый для MCP и настройки.

Существующая установка с `.data` сохраняет её и задания. Галерея доступна только на `127.0.0.1:8876`. Фоновые задания продолжаются без вкладки, пока работают компьютер и процессы.

`npm test` использует временные данные, не ваши аккаунты. Windows/Linux включены в подготовленную матрицу CI; наличие матрицы не доказывает фактический запуск на этих системах.

Автору: `npm run bundle -- /absolute/new/output` создаёт чистую папку и `.tgz`. В ZIP не включайте служебные `._*`/`.DS_Store`. Не архивируйте рабочую папку с аккаунтами, research, отчётами и журналами. Публикация в npm автоматически не выполняется. Подробности: [PRIVACY.md](PRIVACY.md).
