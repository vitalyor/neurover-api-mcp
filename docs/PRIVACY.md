# Учётные данные и проверка исходников

MCP выполняется локально. В исходном коде нет сервера автора для приёма паролей или данных аккаунта и аналитики. Обновление ставится только с согласия пользователя (`neurover_update_apply` с `confirm=true` или команда `update`).

## Передача данных

- Пароль отправляется HTTPS-запросом на фиксированный `https://neurover.io/`. Запрос с паролем не следует перенаправлениям на другой адрес.
- Cookies Neurover не пересылаются стороннему CDN; медиа загружаются по HTTPS-ссылкам сайта.
- GitHub (`api.github.com`, `codeload.github.com`, `raw.githubusercontent.com`): установка и обновление скачивают программу; автоматическая проверка не чаще раза в неделю запрашивает только список тегов. Данные аккаунта, cookies и пути не передаются. `NEUROVER_UPDATE_CHECK=0` отключает автоматическую проверку.
- Установка получает зависимости из npm и браузер средствами Playwright. `--ignore-scripts` отключает lifecycle-скрипты зависимостей. Нативный модуль системного хранилища поставляется готовым для поддерживаемой платформы.
- Модель видит аргументы и результаты MCP. Пароли инструментами не принимаются и в результаты не включаются. Имена файлов, промпты и другие запрошенные данные могут попадать в чат.

## Хранение

| Данные | Где находятся |
|---|---|
| Сохранённый пароль | Системное хранилище ОС; сервис `neurover-api-mcp:ACCOUNT`, имя — email |
| Email и режим | `accounts/ACCOUNT/account.json`, без пароля |
| Cookies | `accounts/ACCOUNT/session.json`, позволяют доступ к аккаунту |
| Задания, журналы и миниатюры | Личная папка данных |
| Однократный пароль | Память процесса на время ручного входа |

Системное хранение использует macOS Keychain / Windows Credential Manager / Linux Secret Service через @napi-rs/keyring. На Linux Secret Service требуется явно, без kernel-keyring fallback. Приложение не скрывает и не обходит запросы ОС. Отказ доступа не приводит к открытому хранению.

Настройки сначала отключают автовход, затем сохраняют и проверяют запись либо удаляют её. Старый credential.json удаляется при успешном переключении. Ошибка оставляет manual/pending и сообщение; повтор settings завершает операцию. Новые plain/encrypted режимы больше не создаются. Старый plain требует миграции, старый encrypted поддерживается до переключения через прежний локальный помощник. Переключение блокирует его ключ. Чужие записи старой macOS-реализации не удаляются.

**Cookies по-прежнему не зашифрованы самим MCP.** Файлы создаются с 0600, папки с 0700 на POSIX; на Windows действует ACL личного профиля, chmod её не заменяет. Доступ к личной папке может дать доступ к сессии. Системное хранение не защищает от полностью скомпрометированной ОС или всех программ, запущенных от вашего пользователя. Нельзя обещать абсолютную защиту только из-за Keychain.

Сессии перечитываются между процессами; старый процесс не должен затереть новую сессию. Восстановление повторяет только чтение, не удаления и платные отправки.

## Точки проверки кода

- `src/vault.js`: нативный адаптер; явный Secret Service, без файлового fallback, ошибки без секретов.
- `src/accounts.js`: режимы, хранение/удаление, pending и совместимость.
- `bin/neurover.mjs`: локальный скрытый ввод, отсутствие паролей в аргументах.
- `src/client.js`, `src/browser-auth.js`: адрес входа, проверка email, cookies, временный браузер; пароль вводится только на странице neurover.io.
- `src/paths.js`, `src/accounts.js`: соседняя папка `../neurover-io-mcp` и прежняя запись Keychain `neurover-io-mcp:<имя>` читаются только в старой установке «на месте» (данные в `.data` рядом с кодом) или при явном `NEUROVER_SOURCE_DIR`.
- `src/credential-file.js`, `src/auth-broker.js`: только совместимость прежнего encrypted режима; IPC не возвращает ключи/пароли.
- `src/media-source.js`, `src/cleanup-web.js`: HTTPS/cookies, loopback и защита операций.
- `src/update.js`, `scripts/install.mjs`, `get.sh`, `get.ps1`: проверка версии, скачивание тега с GitHub, установка версий.
- `src/clients.js`: правка настроек MCP-клиентов с резервной копией.
- `scripts/bundle.mjs`: явный список дистрибутива без аккаунтов и отчётов.
- `package-lock.json`: версии и integrity зависимостей.

Это описание поведения, не независимый сертификат безопасности. Фактические результаты macOS надо отличать от подготовленной поддержки Windows/Linux.
